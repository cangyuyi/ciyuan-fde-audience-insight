# AI 工具与复现说明

## 使用方式

本次优化采用“主 Agent 统筹＋独立专业子任务＋独立复核”的方式完成，不让同一个生成结果自我证明正确。

| 工具／组件 | 实际用途 | 可复核产物 |
|---|---|---|
| DeepSeek Harness / Agent 子任务 | 后端整改、业务洞察、前端原型、独立数据与代码复审 | 代码、报告、复审记录 |
| openpyxl / pandas | 逐份读取 M1–M4、M6，处理订单去重、画像和标签统计 | `agent/data/raw_manifest.json`、复算测试 |
| python-docx | 读取 M5；生成正式 DOCX | 原始观点血缘、正式报告 |
| FastAPI / LangGraph | 受控检索、跨域洞察、引用校验、线程和反馈 | `/v1/*` 真实响应、46 项测试 |
| 原生 HTML/CSS/JavaScript | 会前工作台、证据卡、反方校验、四态反馈 | `/prototype/` |
| Chrome headless | 真实页面自动执行与截图 | `evidence/screenshots/` |
| Archify | 业务与证据治理架构及浏览器检查 | 架构 HTML/PNG、验证 receipt |
| LibreOffice Kit | DOCX→PDF、页面渲染与字体检查 | PDF、页数和视觉验收 |

## 关键提示词模式

### 证据优先

> 每条结论必须包含人群／场景／任务、支持证据、真实材料／sheet／字段／行号、证据等级、反例、不确定性和下一步验证；不能把人工月报、专家观点或品牌A外推写成客观事实。

### 严格质检

> 不接受“HTTP 200 即成功”。检查业务回答是否有证据、同线程追问是否继续 answered、数据版本是否绑定、反馈是否关联真实 run；数值必须回到原始文件独立复算。

### 原始数据接入

> 直接读取 XLSX/DOCX，记录输入文件 SHA256、真实文件名、sheet、字段、行号、清洗规则和时间窗。缺数据标未知，不生成或补齐模拟事实。

### 对抗性原型验证

> 用多域关键词、泛化反方追问、无证据问题、无效引用、PII、active 同版本写入、uvloop 和超时场景测试，不以理想路径替代验收。

## 复现路径

1. 原始材料复算：运行 `audience-agent raw-import` 或 `python -m audience_agent.raw_ingest`，生成证据和 manifest。
2. 后端质量门禁：运行 pytest、Ruff 和 eval，保留命令输出与退出码。
3. 真实原型流程：启动 FastAPI 后运行 `scripts/run_prototype_flow.py`，要求两轮 answered、M2/M3/M4/M5 覆盖和反馈关联。
4. 浏览器佐证：运行 `scripts/capture_prototype.py`，由 Chrome 执行真实页面流程。
5. 文档验收：生成 DOCX/PDF，渲染检查中文字体、表格、编号和实际页数。
